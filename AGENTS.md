# Mundial — instructions for coding agents

This repository is an **OpenSpec change pack** generated by RNC from a legacy system
(workspace `58e6d381-da51-4227-98a5-804213e1fd85`). It holds no application code yet: `openspec/changes/` is the build plan,
`openspec/specs/` is empty on purpose and fills as changes are archived.

**Read `openspec/config.yaml` first and treat its `context` block as standing orders**
(language, stack, author directives, precedence). This file adds how the build runs.

## Loop

One change per run, in this order:

```
  001-project-foundation
  002-clientes
  003-itens
  004-produtos
  005-deployment
```

1. **Apply** — `/opsx:apply <change-id>` (Cursor/Copilot: `/opsx-apply`, Codex:
   `$openspec-apply`). Read `proposal.md`, `design.md` and `specs/`, implement every item
   of `tasks.md` in order and tick it `- [x]` when done. Without the OpenSpec skills,
   follow the same steps by hand.
2. **Verify** — every acceptance scenario in `specs/*/spec.md` has a passing test; every
   task that enforces an `RK-…` key has a `// RK-…` comment where the rule is enforced.
   `openspec validate <change-id> --strict` passes.
3. **Archive** — `/opsx:archive <change-id>` (`openspec archive <change-id> --yes`). Only
   then start the next change.

`tasks.md` is the progress record: it is tracked, and regenerating the pack from RNC
rewrites `openspec/changes/` but never `openspec/specs/` nor the code you built.

## Rules

- Specs are the source of truth. Never edit a spec, or `openspec/specs/`, to make code
  pass. If a spec is wrong, write it under `design.md` § Open Questions and stop the change.
- Do not invent a stack, entity, field or screen absent from the documents. Author
  directives in `openspec/config.yaml` win over everything else.
- Cite business rules by their stable `RK-…` key, never by `BR-…` (that id renumbers).
- **NEEDS REVIEW** rules are ambiguous in the legacy source: read the original code
  through the RNC MCP (`getSourceFile`) when available, implement the most probable
  reading and leave `// TODO(review): RK-… <question>`.
- Fields marked *to confirm* in `design.md` have no traced source column: do not derive a
  column from the field name.
- Reference tables get a read-only list API and dropdowns, never create/edit/delete screens.
- Locale, date and currency formats, input masks and the address services (ViaCEP, IBGE) are
  requirements of `001-project-foundation` › `locale-and-formats`; the **Mask** and **Behavior**
  columns of each change's `design.md` say which field gets which. Never drop a mask because the
  UI library lacks one — compose it from the library's input.
- Later changes to the system follow the normal OpenSpec flow: `/opsx:explore`,
  `/opsx:propose`, `/opsx:apply`, `/opsx:archive`. A change to an archived requirement
  uses `## MODIFIED Requirements` with the whole block copied.

## RNC MCP (optional, recommended)

The MCP configs in this repository read two environment variables — no credential is
committed:

```bash
export RNC_MCP_URL=https://<rnc-api-host>      # the host shown in RNC Settings → MCP, without /sse
export RNC_MCP_TOKEN=<token from Settings → MCP>
```

With it connected: `getRule(workspaceId, "RK-…")` checks an implementation against the
legacy rule, `getSourceFile` reads the original code of a NEEDS REVIEW rule,
`searchKnowledge` answers what the documents leave unclear. Without it the pack is
self-sufficient: proceed, and note in `design.md` which rules could not be verified.
